# Battle for Biternia — v1.0 Scope & Roadmap

Status: agreed scope, not yet implemented.
Companion doc: `game-rules.md` (full rules reference — v1.0 implements a subset).

## What v1.0 Is

A **personal project**, not a public release. The goal of v1.0 is to validate
that the core rules engine from `game-rules.md` (2-player standard game) works
correctly end-to-end — not to ship a content-complete game.

**v1.0 = core engine + minimal playable content**, driven by a **React**
frontend talking to a **Java/Spring Boot** backend over **REST (polling)**.

## In Scope for v1.0

### Rules engine (full fidelity to `game-rules.md`, 2-player standard only)

- Setup: **Hero draft** (snake draft — R1: initiative player picks 1, other
  picks 2; R2: both pick 2; R3: initiative picks 1 → 4 Heroes/player),
  starting powers (1 Power Card per drafted Hero → hand of 4 + draw 4 Basic
  = 8 starting cards), starting 12-card Basic deck, and initial Hero
  deployment onto Tower spaces.
- The 4-phase round loop: Orders (blind/simultaneous) → Movement (alternating)
  → Action (alternating) → Cleanup.
- Combat math: `damage = max(0, attack - defense)`, Hit effects requiring
  ≥1 actual damage, Structures fixed at defense 1.
- Attack keywords: Ranged, Area, Channeled, Interrupt (including LIFO
  interrupt-stack resolution).
- Base Defenses step (Towers/Bit Area Attack 4, alternating activation).
- Tower/Bit destruction rules, including collateral 3 damage to the Bit on
  Tower loss or Hero defeat, and the "Bit unlockable per-lane" rule.
- Universal Actions (Farm, Rest) — **Hire excluded** (Catapult-variant only).
- Leveling (cost = current level + 1), Cleanup gold gain, hand-size-8 draw.
- Shuffle-Free Zone: strict FIFO deck cycling, discard-pile flip on empty
  deck, no reshuffling ever.
- Defeated Hero handling + Hero Card respawn-via-draw.
- Token/keyword set: Confuse, Heal, Immobilize, Pierce, Stun, Shield,
  +1 Attack, Self/Other, Stealth.
- Win condition: Bit reduced to 0 HP.

### Real content (curated subset of the roster, not placeholders)

- **8 real Heroes** (not the full 19) — exactly enough for the real draft
  (each player ends with 4 Heroes; see "The 8 Heroes for v1.0" below) —
  with **real transcribed A/B/C/Z power cards** — Z (Ultimate) included,
  unlockable at Hero level 4 per the normal rules. Card text is transcribed
  from the rulebook/physical cards, not invented.
- The 24 real Basic Action Cards (Strike/Parry/Dash/Defend) — already fully
  specified in `game-rules.md`.
- **The whole board** — real space graph, 3 Towers per side, real gold
  space layout, as described in the physical rulebook.

### Backend (Java, Spring Boot)

- Domain model: `Hero`, `PowerCard`, `BasicCard`, `Deck` (FIFO, no shuffle),
  `Tower`, `Bit`, `Board`/`Space`, `GameState`, `Player`. Split each into a
  **definition** (static reference data: a Hero's kit, a card's printed
  text, the board graph) vs **runtime instance** (a Hero's current HP/level/
  position in an in-progress game).
- **PostgreSQL** stores definitions only: the 8 heroes' transcribed A/B/C/Z
  cards, the 24 Basic cards, and the board layout — reference data, edited
  rarely, loaded at startup/on demand.
- Live game state (positions, HP, hands, decks, current phase) stays
  **in-memory**, single game instance at a time — not persisted. Restarting
  the server loses an in-progress match; that's acceptable for v1.0.
- Phase state machine enforcing legal actions per phase (reject a Movement
  action during Orders, etc.).
- REST API for: submitting Orders (face-down, hidden until both submit),
  submitting Movement/Action choices in turn order, fetching current game
  state (polling), triggering Cleanup.

### Frontend (React)

- Minimal UI: board view, hand view, per-Hero action submission, visible
  game log/phase indicator.
- Polls backend for state; no real-time push in v1.0.
- Enough to actually play a full match by hand and see every rule fire
  correctly — not visually polished.

## Explicitly Out of Scope for v1.0

Carried over from `game-rules.md`'s existing out-of-scope list, plus new
v1.0-specific deferrals:

- 3-4 player team variant, Catapult variant (Hire, jungle spaces).
- The remaining 11 Heroes (of 19) not in the chosen 8, and their Power
  Cards — not transcribed or implemented in v1.0.
- Runika artifact tokens, Bear Trap, Ice Wall (tied to specific Heroes'
  kits outside the chosen 8, unless one of the 8 turns out to need them).
- "To the Pain" arena component (still unclarified).
- WebSockets / real-time push (REST polling only for v1.0).
- Persisting live game state, match history, multiple concurrent games,
  auth (DB in v1.0 is definitions-only — see Backend section).
- Any visual polish, animations, sound.

## Suggested Build Order — Vertical Slices

Rather than building horizontally (all of the domain model, then all of the
engine, then all of the API, then all of the UI), each slice below cuts
through every layer — DB → domain model/engine → REST API → React UI — for
a deliberately narrow scope, then the next slice widens it. This surfaces
integration problems early instead of only at the very end, and gives a
playable (if narrow) system after slice 1.

1. **Thinnest possible slice**: 1 Tower + 1 Bit per side, no real board
   graph yet (a single shared space), 1 Hero per side with just a Strike
   and a Defend Basic card (no Power Cards yet). Wire the full path:
   Postgres holds the Basic card definitions → domain model/engine runs
   Orders → Action → Cleanup only (skip Movement, nothing to move to yet)
   → REST endpoints for submit-order/get-state → React shows board + hand
   + submits a card. Goal: see one full round resolve correctly end-to-end.
2. **Widen the board & phases**: real space graph (all 3 Towers/side, gold
   spaces), Movement phase added, Dash/Parry Basic cards added. Still 1
   Hero per side, still no Power Cards.
3. **Widen to multiple Heroes per side (hardcoded, no draft yet)**: add a
   second Hero per player (2 of the eventual 4), bring in real transcribed
   A/B/C Power Cards for however many Heroes are transcribed so far.
   Exercises turn-alternation logic (Movement/Action alternating across
   multiple Heroes) for the first time. Hero assignment is still
   hardcoded — the draft comes in slice 6, once all 4/side are needed.
4. **Widen to full keyword set**: Ranged, Area, Channeled, Interrupt,
   tokens (Confuse, Heal, Immobilize, Pierce, Stun, Shield, +1 Attack,
   Stealth), Base Defenses step. This is where most rules-correctness bugs
   get caught.
5. **Widen to full round loop**: leveling, Cleanup gold/draw, Defeated Hero
   handling, Hero Card respawn-via-draw, Ultimates (Z cards) at level 4,
   deck-exhaustion/flip (Shuffle-Free Zone).
6. **Widen to full team size + Draft**: implement the Setup snake-draft
   phase (see `game-rules.md`) so players actually draft their 4 Heroes
   each from the full 8-Hero pool, instead of having them hardcoded. Add
   remaining transcribed Heroes' Power Cards as they become available,
   one at a time, until all 8 are in.
7. Play full matches human-vs-human (you controlling both sides) throughout
   slices 3-6 to shake out edge cases as each widening lands, rather than
   saving all testing for the end.

## The 8 Heroes for v1.0

Per the rulebook's recommended starter set — a **shared pool of 8** that
the snake draft (see Rules Engine, `game-rules.md`) runs over. The actual
4-vs-4 split is decided by the draft each game, not hardcoded; the grouping
below is the rulebook's example/expected balanced split, not a fixed rule:

- Archer, Fighter, Cleric, Duelist
- Wizard, Barbarian, Paladin, Hunter
